# 店舗管理画面の実装・検証（2026-11-15）

対象: `specs/ADMIN_SPEC.md` v0.1。

## 実装

- `npm run admin` でループバック専用の管理サーバーを起動。`ADMIN_PORT` と `--production` に対応。
- URLからマニフェスト、名前が完全一致する予約ネットワーク、読み取り専用MCPの `get_shop_info` を解決。HTMLの発見リンク、ネットワークの選択、同一オリジンのリダイレクト、各通信10秒のタイムアウト、MCPセッションとSSE応答に対応。
- 追加・編集・再取得の選択反映・削除確認・並び替え・生成ファイルの一覧表示。MCP取得に失敗した場合は手入力で保存可能。
- `validateShops()` と既存ビルドを再利用。一時領域でビルドし、成功後に店舗データと生成物を反映。反映途中の失敗時も元のバイト列へ復元。保存処理を直列化し、古い一覧による更新は拒否。
- 表示用情報は `admin/cache.json` のみに保存。管理サーバーは許可した3つのUIファイルだけを配信し、キャッシュやサーバーのソースは配信しない。公開 `site/`、公式ランタイム、店舗側ソースには変更なし。

## 追加対応: AIによるジャンル初期入力と保存結果の簡略化

仕様 v0.3 に合わせ、店名・紹介文からGemini Decisions API（`gemini-decision-1` 固定）の選択式分類でジャンルの初期値を決める処理を追加。環境変数または `.env` の `GEMINI_API_KEY` をサーバー側で使用する。管理画面のAI設定・モデル選択とブラウザからのキー送信は削除。店舗の取り込み結果は「保存」を押すまで書き込まず、保存済みのジャンルは再取得しても維持する。保存結果の生成ファイル一覧は画面に出さない。

- 固定の3店舗を入れた一時コピーで `npm test` 91件と `npm run check` が成功。管理画面で操作中の店舗データは差し戻していない。既存テストは特定の3店舗を前提にしているため、店舗数やIDを編集した作業ツリーとは分けて検証した。
- Decisions呼び出しの固定モデル・固定エンドポイント、選択肢と応答の検証、未設定・不正応答・HTTPエラー・タイムアウト、ブラウザからAI設定を送信してもサーバーの設定を変更できないことをテスト。
- 管理画面のブラウザ検証では、Decisions形式のテストHTTP応答と実店舗デモを使用。AI設定画面がないこと、自動入力されたジャンルの手修正、再取得時の保持、取り込み直後に店舗ファイルが未変更であること、保存後に生成ファイル名が表示されないことを確認。
- ユーザーが `.env` に設定したキーを読み込み、Gemini Decisions実APIでも3店の説明文を判定。炉端 灯 → 和食・炉端焼き、トラットリア ソーレ → イタリアン・イタリア料理、広東 龍 → 中華・広東料理を確認。判定結果は店舗ファイルへ保存していない。
- `.env` がgit対象外であることを確認し、管理サーバーを更新版で再起動。管理画面のHTTP 200応答を確認。
