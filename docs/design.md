# 親サイトの操作一覧

現行実装の概要。見直し後の[仕様 v0.3](../specs/restaurant-spec.md)との差分は[仕様見直しメモ](spec-review-2026-11-14.md)を参照してください。ジャンル・場所の確認と店数の事前表示、店ごとの許可カードの廃止、ボタン名は実装へ反映しています。ページ移動の追加確認は未変更です。

画面は利用者の希望に合わせ、条件入力をチャットに統一しています。独立した条件フォームと「Agents working for you」欄は表示しません。AIの設定が必須で、キー未設定なら最初に設定モーダルを開きます。プロバイダーのプルダウンとキー入力を基本の操作にし、モデル・接続先・保存済み設定は詳細設定にまとめます。公式ランタイムの設定フィールドと保存処理を再利用し、設定済みならそのままチャットを開始します。プロバイダー変更時は入力中のキーを消し、保存せず閉じると適用中の設定に戻します。

問い合わせの比較カードと店へ進むボタンもチャット内に表示し、ページ下部の独立した比較欄は置きません。カードの店名は登録店IDから取得します。条件変更後は古いカードを会話の履歴として残し、条件変更の案内を添えて移動ボタンを無効にします。New chatでは会話と比較結果を消します。

ジャンルと場所は親の登録情報で絞ります。`website_confirm_shop_inquiries`が件数を計算し、「この条件だと○店に問い合わせます。問い合わせますか？」と一度だけ表示します。初回の接続説明や店ごとの許可カードは出しません。未確認の希望を勝手に「指定なし」にする呼び出しを拒否し、確認した店だけに接続します。条件変更・New chatで確認を無効にします。入力フォーム生成用のCRUSE設定は外し、希望は短いチャットで聞きます。

| 分類 | データ・状態・操作 | 根拠となる実装 |
| --- | --- | --- |
| 公開データ | 登録店のID・表示名・エリア・料理・ページ/ネットワークURL | `site/shops.json` |
| ページ状態 | 日時・人数・コース要否・任意予算・食材・相談用メモ、version | `site/finder.js` `FinderPage` |
| 読み取り | 日本時間の今日と曜日、ページ状態、登録店の一覧/絞り込み | `getState`, `listShops` |
| 表示変更（可逆） | 条件更新、比較カードの表示/クリア | `setConditions`, `showCandidates`, `clearCandidates` |
| 件数確認（可逆） | 親の情報で絞った店数を示し、開始後だけ対象の店へ接続 | `site/inquiries.js` |
| 移動（確認必須） | 登録店の予約ページへ条件だけをURLフラグメントで渡す | `checkOpenShop`, `openShopPage`, `site/site.js` |
| 外部サービス | 利用者が選ぶLLMルーター、許可された店の公開ネットワークと店自身の読み取り専用MCP | 公式 `runtime/` |
| 対象外 | 予約確定/変更/キャンセル、座席の確保、決済、連絡先の収集、カレンダー/電話、サイト負担LLM | ネットワークのgrounding rules |

店の公開URLはビルド時に検証し、同意ラベル・ツール名・許可オリジン・CSPへ同時反映します。ページ表示時に店へ事前取得や接続テストを行いません。親から店のサイト操作は呼びません。

`show_candidates.expectedVersion` は仕様書の入力に追加した必須フィールドです。チャットから条件を変更するとversionが進み、古い条件の回答を新しい条件の結果として表示するのを防ぎます。移動確認中に条件が変わった場合も、遷移直前の再検証で拒否します。

店舗エリアは店側のシードと照合して新宿・渋谷・横浜に修正しました。サイトの名前・配色は仮の設定です。登録店の実データと公開ホストが確定したら `shops.json` と表示文言を編集し、再ビルドしてください。
