# 店舗紹介の実装・検証（2026-11-15）

対象: `specs/SHOP_INTRODUCTION_SPEC.md` と `specs/ADMIN_SPEC.md` v0.4。

## 実装

- 通常の店舗サイトをタイトル・説明文・JSON-LDから取り込み、日時や人数なしで紹介カードを表示する。取り込み後も「保存」するまで店舗データは変更しない。
- エージェントの有無と予約対応を独立させ、4通りの組み合わせを扱う。予約ネットワーク以外も登録でき、予約非対応店には予約ボタンや予約条件を渡さない。
- 商品・店舗情報の問い合わせには目的と140文字以内の質問を指定し、対象店の承認後に問い合わせる。通常サイトへは問い合わせない。紹介目的のMCPは読み取り専用ツールに限定する。
- 公開紹介文と予約対応・予約URLを管理画面で編集できる。旧形式の飲食店データは予約導線を維持する。

## 自動検証

固定の3店舗を入れた一時コピーでビルド、`npm run check`、`npm test` が成功（108件）。管理画面で編集された作業中の店舗データは差し戻していない。

通常HTMLの取り込み、エージェントと予約対応の4通り、予約用以外のネットワーク、店舗情報MCPを宣言しないエージェント、日時なしの紹介と問い合わせ、紹介文検索、予約条件の非送信、読み取り専用ツールの限定と承認失効、通常店舗のみの保存・ビルドを検証した。

## ブラウザ検証

既存の予約フロー検証が成功。プロバイダー設定、キーの分離、日時条件、比較、古いカード、新規チャット、問い合わせ承認と分割処理、MCP、店舗への引き継ぎを確認。

管理画面と親サイトの結合検証では、別ポートの実飲食店デモ3店と通常の雑貨店・予約非対応の文具店エージェントのテストサーバーを使用した。

- 取り込み・ジャンル修正・再取得・保存・並び替え・削除と既存の予約問い合わせが成功。
- 通常の雑貨店は日時・人数なしで紹介され、店舗リンクが表示される。予約ボタンと外部問い合わせはない。
- 文具店エージェントへ日時・人数なしで商品情報を問い合わせられる。商品情報の読み取りツールは使え、購入ツールはモデルに公開されず呼ばれない。予約ボタンはない。
- 1440pxと390pxで紹介カードを確認。ブラウザのJavaScriptエラーなし。

撮影結果はgit対象外の `test-results/shop-introduction-desktop.png`、`shop-introduction-mobile.png`、`shop-agent-introduction.png`。
