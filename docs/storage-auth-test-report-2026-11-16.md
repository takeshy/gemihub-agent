# Cloud Storage・メールログイン・店舗招待の検証

## 変更

`gemihub-restaurant` の管理対象ファイルを `apps/shop/` に取り込み、npm workspacesとルートのロックファイルに統合した。取り込み元のコミットと、単独起動・Docker/Cloud Buildの構成は `monorepo.md` に記録している。元リポジトリには変更していない。

通常のファイル保存を、店主のDriveからサービスの非公開Cloud Storageへ変更した。認証はネイル・美容室のGoogleログインと、その他の店主のメールリンクを分けた。親の運営者だけがGoogleにログインし、Gmailから招待・認証・通知メールを送る。設定と記録に加え、画像・添付・オフラインページ・版履歴をZIPでダウンロードできる。

## ブラウザ

`npm run test:storage-auth` で実HTTPサーバーを使い、次を確認した。

1. 親の未認証状態では店舗一覧を取得できず、Google側のページを経由してログイン後に招待フォームが開く。外部サイトから戻るトップページは開き、管理APIへの外部サイトからのアクセスは拒否する。
2. 親からの招待依頼が店舗サーバーへ届き、店舗サーバーが共有秘密付きで親のGmail中継へ送信を依頼する。
3. メール送信時点では店舗を作らず、店主がメールアドレスを確認した後に管理セッションと店舗を作る。
4. 店主の画面からZIPをダウンロードでき、設定・記録だけでなく実際の添付と `web/index.html` が含まれる。Driveへのリンクはない。
5. 親の1440pxと390pxで表示を確認。JavaScriptエラーなし。

ZIPは独立したPythonのZipFileでも17ファイルのCRC検証を通過した。スクリーンショットとZIPはgit対象外の `test-results/` に保存した。

Google OAuthとGmail送信はテスト用応答、Cloud Storageは実APIの呼び出し形式のテストとメモリ内保存を使った。実メール・実GCSへの書き込み・本番移行・配備は行っていない。実利用にはOAuthクライアント、許可した運営者、暗号化鍵・共有秘密、非公開バケットとサービス権限の設定が必要。現在のルート `.env` にGoogle認証設定がないことは値を出さずに確認した。
