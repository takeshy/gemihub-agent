# 店舗紹介への拡張（2026-11-15）

飲食店の予約案内に加え、雑貨店・文具店などを登録情報から紹介する。エージェントがない通常の店舗サイトも対象とする。

## 独立した機能

| エージェント | 予約対応 | 利用できる機能 |
| --- | --- | --- |
| なし | なし | 登録情報による紹介、店舗サイトへのリンク |
| あり | なし | 紹介、承認後の商品・店舗情報の問い合わせ |
| なし | あり | 紹介、予約ページへの案内。空席は店舗サイトで確認 |
| あり | あり | 紹介、承認後の問い合わせ、予約ページへの案内 |

ネットワーク名やエージェントの存在だけで予約対応と推定しない。予約の登録情報がある場合だけ予約導線を表示する。

## 登録・取り込み

- マニフェストと公開ネットワークがあれば、予約用に限定せず取得・検証する。複数あれば問い合わせ先を選択する。
- エージェントがなければ、通常ページのタイトル・メタ情報・JSON-LDから店名、紹介文、住所を取り込む。ページのスクリプトは実行しない。
- 予約対応は、店の情報に予約条件と予約URLが明示されている場合に初期設定する。管理画面でも個別に変更できる。
- ジャンルはGemini Decisions API固定。料理に加えて生活雑貨・文具・工芸・ギフト・店舗サービスなどを分類できる。
- 取得できないエリアや紹介文は編集できる。取り込みはプレビューだけで、「保存」するまで店舗データは変えない。

## データと互換性

`shops.json` はversion 1を維持する。既存の `id`・`name`・`area`・`cuisine`・`pageUrl` を使い、`cuisine` は汎用のジャンルとして扱う。

- `networkUrl`: 任意。空ならエージェントへの問い合わせを行わない。
- `description`: 任意、2000文字まで。紹介カードやAIに渡す公開情報。
- `reservationEnabled`: 任意の真偽値。新規取り込みでは明示する。
- `reservationUrl`: 予約対応を有効にした場合に必要。店舗ページと同じオリジン。
- 旧形式で予約対応が未指定の登録店は、従来どおり `pageUrl` を予約ページとして扱う。

ビルドはネットワークURLがある店だけを親AIの接続先に加える。通常サイトは店舗一覧と紹介情報に含める。公開ファイルは静的のまま、公式ランタイムは変更しない。

## 公開サイト

- 紹介目的では日時・人数・コース・食材を聞かない。
- `website_list_registered_shops` と `website_show_shop_introductions` で、公開された登録情報を基に紹介カードを表示する。
- 予約非対応店には予約ボタンを出さず、予約条件のURLフラグメントも渡さない。
- エージェントへの商品・店舗情報の問い合わせは `purpose=introduction` と内容を指定して、対象の承認後に実行する。日時・人数は不要。
- 通常サイトの紹介だけでは外部問い合わせをしない。商品・在庫・価格・営業時間を推測しない。
- 店舗紹介で呼べるMCPは、既知の読み取り専用ツールまたは `readOnlyHint` があるツールに限定する。購入・注文・決済・予約は親から実行しない。
- エージェントがないページからの親AI中継開始は拒否する。

## 検証

4種類の機能の組み合わせ、通常HTMLとJSON-LDの取り込み、予約用以外のネットワーク、予約条件なしの紹介と問い合わせ、予約導線の抑止、読み取り専用ツールの限定、公開データの保存・ビルドを検証する。
